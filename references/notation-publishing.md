# Notation 发布与排版

## 连接和定位

- 使用已安装的 Notation Codex 插件。读取 `notation:notation-workspace`，以 `notation_get_status` 确认连接及账号，以 `notation_get_schema` 确认原生文档与图层格式。断开时按 `notation:notation-setup` 的正式登录流程处理，同时继续 Canvas 发现、归档和笔记准备。
- 用 `notation_list_pages` 核实学期、课程和讲次的完整路径，遍历分页；用 `notation_search` 按讲次、主题、来源或文件名找候选，再读取正文和来源块确认。延用已验证的页 ID，同名凭来源与父页消歧。课程已有对应页时复用；为确实缺页的讲次选择稳定标题。
- 新建页前读取父页的最新版本。增改先读取目标文档与图层，备份受影响的块及其标识；提交工具要求的版本前提。版本冲突时重新读取并对照变更，保留并发编辑；提交超时或结果不明时先查目标 ID 与元素状态再续写，以免重复创建。无法可靠合并用户编辑时保存待改稿和具体冲突。
- 用已公布的 schema 表达可编辑的标题、段落、列表、代码、公式和表格。文字和大量图片可分批发布，每批写入后读回并保存进度。下批使用最新版本，按照已确认的元素 ID 衔接。
- 将需保留或补上的短语级高亮按当前 schema 写成行内原生 marks；若当前发布通道不支持原生高亮，使用简短加粗，不把标记语法当正文。读回时抽查高亮确实落在对应短语，并确认同一位置未重复强调。
- Poe 回复按 [复制后的排版纠错](poe-drafting.md#poe-复制后的排版纠错) 检查公式双份、网页视觉层残留、裸露 Markdown 和重复换行；保留原文的知识内容，同时订正导入失真。不能只用字符总数相等证明复制正确。

## 图片与正文的关系

- 先排阅读顺序。在概念讲解后放最能说明关系的图，在推导或操作展示后就近放结果图。需要追踪箭头、坐标轴或细字的大图使用接近正文宽度，单一控件或局部特写采用较窄尺寸。裁剪优先去掉页眉、页脚和无关留白。
- 常规插图用原生图片层并锚定稳定的正文块，按当前 schema 设置相对顺序、位置和尺寸。给成对图保留一致比例和适量留白。确认当前渲染器实际支持两个原生图层并排时可独立排布；否则把相关面板合成一张留有中缝的图，再锚定到对应段落。图注分别注明各面板的状态或源页。字号缩小后若难读，就改用宽图或上下排列。
- 只有正文已留出空间且能实际检查应用渲染时采用自由定位。沿同一边距对齐，标题、正文与图片之间留出节奏一致的间距。横向比较图应共用尺度或明确给出各自尺度。通过正文解释关键箭头、标签和读图顺序。
- 原图保留有教学意义的标签和图例，在图外给出简短图注与源文件页码。真实代码效果图只展示运行结果；状态、时间点与条件在图外说明。原图生成和效果图验证按 [笔记质量与复审](note-quality.md) 执行。

## 资源上传与验收

- 使用插件支持的本地文件或二进制上传能力，写入随页面同步的图片资源；上传时使用的数据编码仅作为传输参数。持久引用使用平台返回的资源关联。保留可读分辨率，较大图片按大小分批，先验证小批是否正常。私人课件不上传到公共图床，不把本地路径、临时签名链接或外部数据 URI 当作持久引用。
- 每批重新读取页面和元素，核对父页、正文、资源关联、图层尺寸、锚点、顺序及图注。确认课件原图、已有图片、用户笔迹和子页完整。若桌面端将流式锚点转为定位图层及与图片 ID 对应的占位块，核对同一图层 ID、紧邻正文锚点的占位块与实际位置，再决定是否需要修复。在 Notation 应用中逐节检查清晰度、裁切、重叠、图旁解释和代码配图。若只能完成插件读回，则单独记录应用内显示尚待检查；图片传输失败则保留正文并把对应图列为待补。
- 清单保存源哈希、Notation 页 ID、图片层 ID 和已实际核验的状态。再次运行时先检查这些标识，按漏项续跑。没有可用页面深链接时，用课程路径和标题指明位置。
