# 学习导向的笔记质量与复审

生成或修订教学笔记前完整阅读本参考。目标是让读者理解、推理并迁移知识，而不是获得更长的摘要。下面的深度标准用于每次新增 lecture；跨课程复审仅在用户要求时执行。

## 1. 证据与学习范围

- 课件及课程明确发布的材料决定教学内容与边界。先读完整相关材料、同课程已有笔记，再选择展开位置；不能只读搜索摘要、前几页或旧笔记就宣称完成 review。
- 有已归档且有权访问的 final past papers 时，结合它们理解所需能力：定义与区分、解释机制、分析情境、逐步计算、追踪代码或评估方案。它们用于调整讲解深度和练习方式，不替代课件，也不证明本学期会采用相同范围或形式。
- 常规同步可使用已有试卷，不因此自动扩大为登录其他平台、下载历年卷或重写全学期。用户明确要求复审时，盘点其指定范围内每科的课件、试卷、现有笔记，分别记录可读性与覆盖情况。
- 没有相关试卷、课程无 final、试卷缺页、扫描文字不清或课程版本不匹配时，依据可核实课件和本课程适用的评分要求继续；不能编造试卷内容、推断未发布章节，或宣称所有课程均已结合完整试卷。
- 语言与传意课围绕受众、信息选择、论证、证据、段落组织、技术解释、表达与修订深化；不要强套编程或计算题的结构。课程给出的 GenAI 和作业规则仍适用，学习示例不能变成代写个人评核提交。

## 2. 隐性使用试卷，不透露出题线索

- 在笔记正文、标题、标签、图注、自测、公开索引中，不标出「考点」「重点考」「高频」「必考」「曾考」「真题对应」或相似暗示；也不提供年份、题号、频次、分值分布与知识点的对应关系。
- 不直接复制、近似改写或解答实际试卷题作为笔记示例。使用新的情境、数据或代码来演示知识的推理方法，不能仅改名字和数字就把原题隐藏进笔记。
- 若旧教学笔记已有出题标签或题目答案，复审时将可保留的教学内容改为中性的概念解释，去掉考试关联；独立试卷原件及用户个人批注不在此规则下被删除或静默改写。
- 来源标注仍保留课件文件、页码和稳定链接。不要在学习笔记中附试卷分析表或能反推出具体试题的映射。完成报告可说明参考了可用试卷，但不披露某个知识点为何被加深。
- 必要的试卷模式记录仅保存在私有本地工作记录，不写入面向用户的学习笔记或公开 skill 仓库。续跑清单只需记录版本、覆盖、待办等元数据，不需要保存逐题映射。

## 3. 深度与层次

依学科、章节选择必要内容，不固定模板、不用篇幅或小标题数量代替质量：

- **知识关系**：说明本节在课程中的作用、必要前置知识，以及与相邻概念的联系；主干、细节和补充解释要有层次。
- **准确概念**：先用完整、直白的句子解释对象是什么、做什么及得到什么结果，再引入英文术语。确有易混概念时按同一准则比较；不要机械地给每个定义添加「不是什么」或边界提醒。
- **机制与推导**：解释为什么成立，展示中间步骤、因果、状态变化或信息流。公式说明变量、单位和假设；代码说明初始状态、执行顺序、输出及不确定性，不能跳到答案。
- **示例与迁移**：用适量独立示例完整走一遍推理，再改变一个条件说明结果如何变化。情境须标明是假设；不虚构研究数据、个人经历或老师意见。
- **选择与代价**：涉及方法、设计或方案时，说明在什么条件下选择它、怎样解决问题、有什么限制或取舍。避免只罗列优缺点名称。
- **表达类课程**：展示主张—证据—解释—意义的链条；给出薄弱段落与改进框架，解释修改理由。区分事实、计划和预测，保留证据中的范围和限定。
- **自检与练习**：用新的任务检验能否解释理由、完成步骤、诊断错误或迁移条件。提供解题思路或核对方法，不仅给结论；不得暗示题目与考试记录有关。

重要内容通过更完整的解释与章节组织自然体现，不额外贴考点标记；仍覆盖课件必要内容，不能只保留试卷涉及的部分。补充例子可简洁标为「例」，必要的来源纠错或版本差异放在对应脚注或折叠补充中，不在正文反复解释笔记编写过程。

## 3.1 课件覆盖优先：详细笔记不是压缩摘要

- 先按课件的章节或连续页组建立轻量覆盖清单：来源与版本、页码、实质知识单元、现有笔记位置、状态（充分／过简／遗漏／待核实）。逐节核对，而非用标题命中或全文关键词判断已覆盖。封面、重复页、纯行政信息可以说明后合并或省略；教学性内容不能因为篇幅或试卷未涉及而静默删掉。
- 保留课件中独立的概念、分类项、步骤、假设、适用条件、限制、异常情况、比较维度及有教学作用的例子。一个枚举列表不能只保留总标题；说明每个有实质意义的条目及条目之间的区别。表格、图中的标签／关系、代码结果和讲义补充也纳入核对，文本提取不清时回看原页。
- “提到术语”不等于“解释充分”。读者应能凭笔记重建机制或步骤、解释例子为何得到该结果，并指出条件改变后的差异；达不到时在相应位置展开。避免用泛泛的学习建议或重复定义代替缺失的课程内容。
- 课件例子应说明设置、过程、结论与它要展示的概念；计算保留中间步骤和单位；代码解释参数、控制流、输出及失败路径。已有原图和效果图保留在对应知识点旁，不能以图片替代文字解释，也不能只留代码而不解释可观察结果。Web 等视觉代码在效果有助理解时提供真实渲染或关键状态对比，注明补充样式／资源及静态动画的限制。
- 结构用“主题 → 子概念 → 机制／例子／边界”组织，先建立关系，再提供足够细节。不要设统一字数或机械加长：简短而完整的导论可维持原样，内容密集的一讲则允许更长或使用合理折叠，但不可把必要知识藏成无解释的名词清单。
- 发布前逆向检查每个实质知识单元是否有明确落点。覆盖不足、源页不可读或来源缺失时记录具体待办，不标记整篇已完成。覆盖清单和原笔记备份留在私有工作记录，不把课件、个人路径、Notion ID 或考试映射提交到公开技能仓库。

## 3.2 清楚展开，不堆术语或说教式提醒

- 用户指定历史笔记作范例时，实际阅读有代表性的页面，并在源课件可读时对照其解释方式、信息密度和忠实度。学习其讲解方式，不沿用其中的技术错误、考试标签或聊天式结尾；没有原课件时不得声称已验证忠实度。用户已认可的改写样例优先作为后续尺度，无需每篇重复征求风格确认。
- 一段集中讲一个概念。先交代具体对象或情境，再展开动作、原因和结果；首次出现的缩写说明含义。枚举项逐项解释，执行流程按顺序展开，避免把多个术语、因果和取舍压进一句话。
- 详细指课程信息与解释充分，不是术语更密、句子更长。保留源课件的实质细节与示例；将过密段落拆开，并把补充整合进原章节，不追加一层层重复的「深化说明」。
- 删除不增加课程知识的泛泛劝诫、免责声明和编写说明，例如反复强调「不能据此推断」「这不是忽略某事的理由」「这些是笔记补充」。不要把内部质量检查、版本审计和学习建议铺进每个知识点。
- 保留会改变定义、公式、代码结果或方法适用性的具体条件，并与对应知识一起解释。确有来源错误或版本冲突时简明指出，可放折叠补充；不能为了减少提醒而抹掉技术上必要的限定。
- 发布前通读：读者是否不翻原课件也能理解每一步？是否仍有未解释的术语串？能否删除某句话而完全不损失课程知识？最后一类句子通常应移除。来源覆盖、核对过程与待办留在私有工作记录。

## 4. 旧笔记安全深化与验证

- 用户要求复审时，不因「已有完整笔记」或「源哈希没变」而跳过。先备份原正文与页面/块标识，盘点课件原图、引用、子页与用户内容；备份保留在私有本地，不提交公开仓库。
- 找出缺失的关系、推导、示例或必要条件，在对应章节用唯一稳定文字或块标识定位，做局部纠错与重组。用户要求改写风格时，可重写完整的正文段落或章节，而非只追加文字；先备份并保留图片、子页和用户内容，不盲目整页覆盖。
- 个人稿件、个人事例、作业答案和批注默认保持不动；明确的修改授权优先，无法区分时询问。保留原图及其上下文，新增解释不能使图文错配。
- 发布后重新读取，核对新增段落实际存在、内容没有截断、公式/代码格式正确、图片/子页/引用未意外丢失。图片数量相同不能单独证明图片内容和位置未变；如操作触及图片或布局，再检查对应块及显示。
- 记录逐页的来源覆盖、深化状态和待办；最终按实际完成范围汇报。部分页完成、试卷不全、图片待补或未发布章节不能被概括成「全学期全部完成」。
